# 观影签到日常任务 设计

日期：2026-08-18
状态：已批准

## 背景

游戏「向僵尸开炮」新增限时活动「观影签到」：战斗页左侧活动入口进入，页面内含「免费领取」签到按钮和「观影便利店」子入口（可免费领救援/远征入场券）。

页面对象与图片模板已就绪（git 未跟踪的新文件），本次只做日常任务接入：开关 + 任务。

| `src/pages/观影签到.ts` | 页面识别图 + `免费领取()`（while 循环点按钮，点完点屏幕底部关弹窗）+ 到观影便利店路由 |

`免费领取()`/`免费()` 均为 while 循环：按钮已消失（已签到/已领完）时循环不执行，直接返回 true，不会误报失败。

## 范围

本次只做：2 个日常开关 + 2 个日常任务。**不做**页面逻辑修改、不新增图片。

## 设计

### 1. `layout/layout.xml` — 日常 tab 加 2 个开关

对齐「缘聚七夕_鹊桥祈缘/相思赴约」先例（每个活动功能一个开关），放在缘聚七夕开关附近：

```xml
<pref-switch id="观影签到_签到" text="观影签到-签到" checked="true" layoutDirection="rtl" />
<pref-switch id="观影签到_观影便利店" text="观影签到-观影便利店" checked="true" layoutDirection="rtl" />
```

### 2. `src/MainWindow.ts` — 类型声明加 2 个字段

```ts
观影签到_签到: ConfigurableView<PrefSwitch> & JsCheckBox
观影签到_观影便利店: ConfigurableView<PrefSwitch> & JsCheckBox
```

### 3. `src/model/daily.ts` — 战斗区块加 2 个任务

放在「缘聚七夕」任务块之后、基地区块之前（入口在战斗页）：

```ts
if (isDailyEnabled('观影签到_签到')) {
  doTask('观影签到 签到', function (): boolean {
    if (!nav(观影签到)) return false
    return 观影签到Page.免费领取()
  })
}
if (isDailyEnabled('观影签到_观影便利店')) {
  doTask('观影便利店 免费', function (): boolean {
    if (!nav(观影签到)) return false
    if (!nav(观影便利店)) return false
    return 观影便利店Page.免费()
  })
}
```

同步：import 观影签到/观影便利店页面、实例化页面对象。

### 导航与回退

- `nav(观影签到)`：Router BFS 从当前页自动寻路（战斗 → 观影签到 一步直达）
- `nav(观影便利店)`：观影签到 → 观影便利店（路由已配置）
- 任务结束后页面停在观影签到/观影便利店（两页无出口路由），后续任务导航时 Router 逐层 back 自动回战斗，与现有缘聚七夕/鹊桥祈缘模式一致

## 测试

`npm run build` 编译通过；真机跑 daily 验证签到与领券动作。无法本机模拟游戏 UI，UI 行为需真机验证。

## 错误处理

- 导航失败 → `nav()` 返回 false → 任务跳过（现有机制）
- 按钮不存在（已签到/已领完）→ while 循环直接退出，返回 true
- 活动未开放 → 战斗页找不到入口图，Router 抛「按钮不存在」→ doTask catch → 计失败
