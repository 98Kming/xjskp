# 详细日志开关 设计

日期：2026-09-18
状态：已批准

## 背景

脚本长期在设备后台运行，AutoJs6 控制台日志在脚本结束/进程重启后不可回溯，排查问题（导航失败、找图未命中、任务跳过）缺少现场。需要把运行期间的日志持久化到设备文件，供事后查看。

## 范围

设置页（viewpager 第 4 页）新增「详细日志」开关：

- 勾选：本次运行的全部日志（约 200 处既有 `log()` / `console.*` 调用，含 Router 导航链路、找图、任务进度）除输出到控制台外，同时写入设备文件
- 未勾选：行为与现状完全一致（不写文件）
- 开关状态持久化：由 `PrefSwitch` 基类机制免费获得（`storages.create("pref")`，key = `详细日志_checkbox`）

**不做**：不新增细粒度调试输出（如找图坐标、点击点），不改任何既有日志调用点。

## 设计

### 1. `layout/layout.xml` — 设置页加开关

对齐「执行完息屏」「执行结果通知」现有写法：

```xml
<pref-switch id="详细日志" text="详细日志" layoutDirection="rtl" />
```

### 2. `src/MainWindow.ts` — 类型声明加字段

```ts
详细日志: ConfigurableView<PrefSwitch> & JsCheckBox
```

### 3. `src/main.ts` — `start()` 内按开关配置

用 AutoJs6 官方 API `console.setGlobalLogConfig`（声明见 `declarations/autojs6/aj6-int-console.d.ts:240`，文档名 "Configuration of saving Auto.js logs to local storage"），该 API 将 console 输出写入本地文件：

```ts
// AutoJs6 文档: console.setGlobalLogConfig / resetGlobalLogConfig / files.ensureDir / files.path
var 日志目录 = files.path('./logs')
if (mainWindow.window.详细日志.isChecked()) {
  files.ensureDir(日志目录)
  var d = new Date()
  var pad = function (n: number) { return n < 10 ? '0' + n : '' + n }
  var 日志文件 = 日志目录 + '/运行日志-' + d.getFullYear() + pad(d.getMonth() + 1) + pad(d.getDate()) + '.log'
  console.setGlobalLogConfig({
    file: 日志文件,
    maxFileSize: 512 << 10,
    maxBackupSize: 5,
    immediateFlush: true,
  })
  log('[日志] 详细日志已开启: ' + 日志文件)
} else {
  console.resetGlobalLogConfig()
}
```

要点：

- **读取时机**：`start()` 开头读一次。全部任务入口（启动/开始任务/兑换码/探索/获取队友信息）都经 `start()`，一处覆盖所有流程；运行中改开关不生效
- **日期命名**：同一天多次运行追加同一文件；超 512KB 由 log4j 自动滚动，保留 5 个备份
- **路径**：`files.path('./logs')` 解析到脚本工作目录下 `logs/`（预期 `/storage/emulated/0/脚本/向僵尸开炮/logs`，首次运行打印实际路径确认）
- **关闭时复位**：`setGlobalLogConfig` 配的是 log4j 全局 root logger（非单脚本作用域），只在 AutoJs6 进程存活期内有效；关闭时 `resetGlobalLogConfig()` 收敛状态，避免"上次开过、这次关了还在写"

## 已知限制（验证时注意）

1. **全局配置副作用**：可能把 AutoJs6 应用自身日志一并写入同一文件（污染程度不确定，首次真机验证检查）
2. **待真机确认的不确定项**：
   - `files.path('./logs')` 的实际解析目录
   - `maxFileSize` 滚动行为与备份文件命名
   - `resetGlobalLogConfig()` 在从未配置过时调用是否无害

## 测试

依赖 AutoX.js 运行时 API（`console.setGlobalLogConfig`、`files`），无法在 Node 侧单测，走真机验证：

1. 勾选开关 → 启动任一次任务 → 确认 `logs/运行日志-YYYYMMDD.log` 生成，内容含导航/找图/任务日志
2. 取消勾选 → 再启动 → 确认该文件不再增长
3. 勾选状态在 AutoX.js 重启后保留（PrefSwitch 持久化）

## 实现修订（真机实测，2026-09-18）

实现后的真机验证推翻了设计中的三处假设，实现按实测结论修订：

1. **运行时是 AutoX.js v6.6.7**（包名 `org.autojs.autoxjs.v6`），不是 AutoJs6。项目 declarations 是 AutoJs6 类型，两者 API 有差异，实现前须以设备实测为准
2. **`console.resetGlobalLogConfig` 在 AutoX.js 不存在**（设备实测：`console` 有 `setGlobalLogConfig`，无 `resetGlobalLogConfig`）。关闭路径改为把输出导向 `/dev/null`（丢弃），可反复切换且不触碰其它 appender
   - 备选 `Packages.org.apache.log4j.LogManager.resetConfiguration()` 实测可关闭，但会清空全部 appender（含 logcat 通道），弃用
   - 备选 `LogConfigurator(setUseFileAppender(false)).configure()`：未传 `maxFileSize` 时有效、传了之后失效，行为不一致，弃用
3. **相对路径基准 = 脚本 cwd = 项目根**（`/storage/emulated/0/脚本/向僵尸开炮`），日志目录为 `files.path('./logs')`，与图片路径 `images/xxx.png` 同基准。注意 exec_code 等外部执行环境的 cwd 不同（`/脚本`），不能作为路径验证依据
4. `main.ts` 中 `setupDetailLog` 调用包 try-catch：日志配置失败不阻塞任务启动（原实现崩溃点在 `start()` 内且未捕获，会导致整个任务无法启动）
