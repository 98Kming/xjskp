# 图片路径集中管理设计

日期：2026-08-25
状态：已批准

## 背景与问题

全仓 289 处图片引用以硬编码字符串字面量（`'images/xxx.png'`）散落在约 50 个文件中。图片文件名携带参数（搜索区域 + 匹配阈值 + 缓存策略编码在后缀，如 `$关闭1_0_0.8_800_400_1020_627.png`），屏幕适配重裁图片时区域参数变化必然导致文件名变化，需要在所有引用处同步修改。

典型痛点（2026-08-25 提交 `5b0cdd3`）：`$关闭1` 重裁后需改 3 个文件（Game.ts、玩法商店.ts、img.ts），`接受邀请列表$$_接受` 改 2 处。

关键约束：图片文件名本身是参数（不是纯资源名），"换文件同名覆盖"不可行，重裁必改名。因此核心需求是**改一处、全生效**——集中管理路径常量。

## 方案选型

对比过三种方案：

| 方案 | 内容 | 结论 |
|------|------|------|
| A. 只抽跨页共用图 | 25 张多文件引用的图集中到共享文件 | 改动小但页面私有图（85%）重裁仍要 grep |
| **B. 每页头部 IMG 映射 + 共享文件（选定）** | 页面私有图进本页头部映射，跨页共用图进共享文件 | 每页图片一眼可见，重裁只改头部一处，可增量迁移 |
| C. 全量中央注册表 | 200 张图全部集中 | 大表难维护、通用按钮无归属，收益不增 |

选定方案 B：页面私有图是大多数，散在函数内部最伤；B 让每页图片集中在头部，且改造有局部性、可随时暂停。

## 现状数据

- 图片引用总数：289 处，约 50 个文件
- 跨文件引用的图片：25 张（5 张被 3 个文件引用，20 张被 2 个文件引用）
- 图片访问已全部经过 [src/utils/img.ts](src/utils/img.ts) 封装层（`imageDetector`/`createRouteAction`/`createPageDetector`/`imageNameParser`），路径字符串是唯一的"脏数据"
- 无动态拼接路径，全部为字面量
- routes() 中 `action`/`imagePath` 成对出现同一路径字符串

### 2. 每页头部 `IMG` 映射

每个引用图片的文件（pages/ 与 model/ 下，如 Game.ts、探索.ts、daily.ts）顶部新增：

```ts
import { sharedImages } from '../images'
const IMG = {
  ...sharedImages,  // 跨页共用图透传；页面私有键若重名则私有优先
  页面: 'images/基地_0_0.9_647_2329_1080_2370.png',
  历练大厅: 'images/基地$历练大厅_1_0.9_190_1099_387_1154.png',
}
```

- 页面私有图键名无前缀（页面内唯一即可）
- `...sharedImages` 透传跨页共用图，页面内统一用 `IMG.xxx` 访问，无需区分私有/共用
- 键名冲突规则：页面私有键若与 sharedImages 键重名，页面私有键覆盖（映射顺序 `{ ...sharedImages, 页面私有... }`，展开在后者优先）；如无必要不重名
- 文件内所有 `'images/xxx.png'` 字面量替换为 `IMG.xxx`（`is()`、`routes()`、`back()` 等全部）
- routes() 中 `action`/`imagePath` 成对替换为同一 `IMG.xxx`
- `src/utils/img.ts` 内部引用（closeButtons、find_队友 等）直接 `import { sharedImages }` 使用

### 3. 迁移顺序

分 3 批，每批独立可验证、可 commit：

1. **建 `src/images.ts`**（纯新增，25 张共用图，不引用任何旧代码）
2. **迁移共用图引用**：Game.ts、img.ts、战斗.ts 等涉及共用图的位置改用 `sharedImages.xxx`（直击最大痛点）
3. **逐页迁移私有图**：按引用数降序（战斗 32 → 随机事件 27 → 探索 20 → daily 12 → …），每页一个 commit，可随时暂停

### 4. 验证

- 每批后 `npm run build` 通过（Rhino 兼容约束：无箭头函数/const/解构问题——沿用现有 TS 风格即可）
- 迁移完成后 grep 确认 `src/` 下无残留 `'images/` 字面量（`src/images.ts` 除外）
- 纯常量提取，无逻辑改动，行为不变

## 不做的事（YAGNI）

- 不做 webpack require.context 自动索引（文件名是参数，同名覆盖不成立，间接查找反伤调试）
- 不做全量中央注册表（维护成本高，收益不增）
- 不改动 img.ts 的封装 API（路径来源变化不影响执行层）
