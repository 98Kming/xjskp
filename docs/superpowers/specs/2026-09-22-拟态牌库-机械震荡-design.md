# 拟态牌库 / 机械震荡 日常任务 设计

日期：2026-09-22
状态：已批准

## 背景

游戏「向僵尸开炮」新增两个限时活动：「拟态牌库」「机械震荡」。两者入口都在战斗页左侧活动列表，进入活动页后点页内「任务」按钮到任务页一键领取——与已实现的「天空秘境」完全同构。

图片模板已就绪（git 未跟踪的新文件），本次做页面类 + 日常任务接入。

## 设计

### 1. `src/pages/拟态牌库.ts` / `src/pages/机械震荡.ts`（新建）

与 `src/pages/天空秘境.ts` 逐行同构，仅识别图路径不同：

```ts
import { BasePage, Route } from './BasePage'
import { createPageDetector, createRouteAction } from '../utils/img'
import { 任务 } from './任务'
import { sharedImages } from '../images'

const IMG = {
  ...sharedImages,
  页面: 'images/拟态牌库_1_0.9_918_1633_972_1662.png',
}

export class 拟态牌库 extends BasePage {
  name = '拟态牌库'
  is = createPageDetector(IMG.页面)
  private 任务Action = createRouteAction(IMG.任务)

  click_任务(): boolean {
    return this.任务Action()
  }

  routes(): Route[] {
    return [
      { target: 任务, action: this.任务Action, imagePath: IMG.任务 },
    ]
  }
}
```

`机械震荡.ts` 同结构：类名 `机械震荡`、`name = '机械震荡'`、`页面: 'images/机械震荡_1_0.9_767_2275_854_2318.png'`。

### 6. `src/pages/战斗.ts` — 加 2 条入口路由

**（实现阶段补充：初版设计遗漏本节，真机验证时 Router 报「从"战斗"无法到达"机械震荡"」才暴露）**

战斗页 `routes()` 里每个战斗页活动都有一条 `战斗 → 活动页` 路由，新页面必须同样注册，否则 Router 的 BFS 找不到路径：

```ts
{
  target: 拟态牌库, action: function (): boolean {
    var action = createRouteAction(IMG.战斗拟态牌库)
    if (action()) return true
    self.scrollDown()
    if (action()) return true
    self.scrollUp()
    return action()
  }, imagePath: IMG.战斗拟态牌库
},
```

机械震荡同结构。同步 import 两个页面类。

### 导航与回退

- `nav(任务, 拟态牌库)`：不在拟态牌库页时先导航过去，再由页面路由 `拟态牌库 → 任务` 一步直达
- 领完停在任务页，批量循环随后 `nav(战斗)` 回战斗页继续扫描下一个入口，与现有活动一致
- 活动未开放时战斗页找不到入口图，该目标不会被扫描到，不产生任务记录

## 测试

`npm run build` 编译通过；真机跑一轮日常，看日志确认「拟态牌库 领取」「机械震荡 领取」两项执行结果。

本次不写 test/*.ts：页面代码为纯图片识别 + 固定导航，无可分支逻辑，可断言项（图片路径存在、路由连通）在真机日志中同样能直接暴露。

## 错误处理

- 导航失败 → `nav()` 返回 false → 任务跳过（现有 doTask 机制）
- 页面识别图未匹配（活动页改版）→ Router 回退重试后报「入口点击后未进入页面」，该任务计异常
- 开关关闭 → 不加入目标列表，也不触发批量执行
